## Notes

- Models: the workshop allowlist policy (`ws-bedrock-model-allowlist-policy-1` on `WSParticipantRole`) explicitly denies Sonnet 5.5 and Haiku 5.5. In use: `us.anthropic.claude-sonnet-5` (large) and `us.anthropic.claude-haiku-4-5-20251001-v1:0` (small). If organizers allow 5.5, change `MODEL_*` in `.env` and re-run `backend/infra/ec2_role.py` so the role's policy follows.
- Checks in `backend/infra/` (run from the repo root with `backend/.env` loaded): `converse_smoke.py` (one forced-tool call per model), `concurrency_test.py` (50 small, 8 large in parallel), `guardrail_test.py` (injection flagged, clean passes), `ec2_role.py` (create or update the role, `--dry-run` prints the policy).
- Deploy (A-deploy). The repo is private, so nothing on EC2 clones it and no GitHub token exists anywhere. `bash backend/infra/deploy.sh` (laptop, repo root) archives the HEAD commit to `s3://<VAULT_BUCKET>/deploy/`, then SSM runs `backend/infra/remote_deploy.sh` on the instance: pull with the instance role, extract to `/opt/axelrod` (venv kept), `pip install -r backend/requirements.txt`, restart `axelrod`, print `deployed_sha=` and `healthz=`. `--ref <commit>` ships another commit, `--upload-only` only uploads. Uncommitted edits never ship.
- First boot: `backend/infra/userdata.sh` is a template, filled by `backend/infra/render_userdata.py <out>` from `backend/.env` (env wins). It installs python3.11, user `axelrod`, `/opt/axelrod/.venv`, `/etc/axelrod.env` (STORE=aws, region, resource names, model ids, PRICES_JSON, concurrency, budget, `DATA_DIR=/var/lib/axelrod`, `AXELROD_ENV_FILE=` so no `.env` is read, never credentials), the systemd unit, then runs the same `remote_deploy.sh`. Log: `/var/log/axelrod-userdata.log`.
- Launch command used: `aws ec2 run-instances --image-id <al2023 ssm param /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64> --instance-type t3.medium --subnet-id <default us-east-1a> --security-group-ids <axelrod-api-sg> --associate-public-ip-address --iam-instance-profile Name=axelrod-ec2 --metadata-options HttpTokens=required,HttpPutResponseHopLimit=1,HttpEndpoint=enabled --block-device-mappings DeviceName=/dev/xvda,Ebs={VolumeSize=16,VolumeType=gp3,Encrypted=true} --user-data file://<rendered> --tag-specifications <project=axelrod on instance and volume>`. Upload the tarball first so the first boot serves.
- IMDSv2 is required with hop limit 1: the gateway does not refuse link-local hosts, and a plain GET to 169.254.169.254 gets 401 without the PUT token.
- Remote shell and settings: `bash backend/infra/remote.sh '<command>'` runs one command as root over SSM and prints its output (`journalctl -u axelrod -n 50`, the userdata log). `bash backend/infra/remote.sh --set-env KEY=VALUE ...` rewrites those keys in `/etc/axelrod.env` and restarts the service. `deploy.sh` never touches `/etc/axelrod.env`, so keys set this way (TEST_PAGE_URL) survive redeploys.
- The integration URI uses the instance's public DNS. A stop and start changes it: then `aws apigatewayv2 update-integration --api-id <API_ID> --integration-id <API_INTEGRATION_ID> --integration-uri http://<new dns>:8000/{proxy} --region us-east-1`. API Gateway HTTP APIs time out after 30 s per request, so long-polls must stay under that.
- CORS: the API's CORS config allows any origin, method and header (max age 600 s), and the app's own CORS middleware allows the same. Preflights reach the app through the `ANY` route and come back 200 with `access-control-allow-origin: *`. Port 8000 is open to the internet, so anyone with the instance DNS can skip API Gateway: set `AXELROD_API_KEY` if that matters.
- `TEST_PAGE_URL=<invoke URL>/test-pages/injection.html` is set in `/etc/axelrod.env` only (planted page, simulated, served by the API itself with `x-axelrod-simulated: true`). `backend/.env` has it as a comment so local runs keep the plan.json URL.
